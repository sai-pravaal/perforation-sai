Phase 10 Completion Summary: Frontend Application Shell

The Phase 10 desktop shell is established with frontend/main.py as the application entry point, frontend/main_window.py as the top-level Qt window, frontend/client.py as the sole frontend bridge to backend.api, and frontend/theme/style.qss as the initial shell theme.

The shell contains no pipeline, image-processing, or direct data-access logic. Backend calls are routed through Client.safe_call so UI code receives structured success or failure responses. The frontend does not import OpenCV, NumPy, SciPy, rawpy, scikit-image, or shapely.

A focused import test in tests/test_frontend_shell.py verifies that the application entry point, main window, and API client are importable. No synthetic images or specimen datasets were created. Phase 11 remains pending and must not begin without explicit approval.

Update (2026-10-25 audit): main.py now follows the frontend specification boot sequence: it loads theme/style.qss before any widget exists, calls check_incomplete_session, shows the modal ResumeSessionDialog when a session was interrupted, then constructs MainWindow(client, session_id). MainWindow hosts six tabs in pipeline order (Upload, Session Log, Processing, View, Results, Validation), a File menu (Export Session, Reset Session, Quit), Help > About (version metadata), and a status bar with the session id and current phase. The global gating rule disables Session Log onward until the Upload checklist passes and Processing until the session log is saved and the shadow-bleed check acknowledged. client.py keeps one current session id, adds call_async (QThreadPool worker with GUI-thread delivery) for long operations, and unwrap() as the shared response handler; unknown actions return a structured error. style.qss is the full dark palette with card, tab, button, status, severity-pill and low-confidence badge styles. Open items that still block full compliance (decision needed or needs real capture data): API-01 no upload/start entry point in the frozen 29-function API (files must be placed in raw/ and the run is started through reprocess_from_stage step 1); API-03 no PDF report entry point in the API (Export PDF button disabled); STAT-01 summed-z cutoff 3.0 versus the L2 norm of 14 z-scores; STAT-02 shadow_direction_deg z-scored linearly although circular; PIPE-05 interior holes forced onto an edge; PIPE-06 tooth chord points in the circle fit; PIPE-07 backlit exterior and tooth detection; PDF-01 table width; SESS-06 client.py error convention differs between the plan and the frontend spec.
